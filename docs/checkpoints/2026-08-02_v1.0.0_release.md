2. Data Sources

Three job sources are integrated:

Arbeitnow
RemoteOK
Jooble

Each source is implemented as an independent extractor and normalizer.

Source workflow:

API request
↓
fail-fast response validation
↓
raw JSON save
↓
MinIO raw upload
↓
batch_id generation
↓
source-specific normalization
↓
quality checks
↓
processed CSV save
↓
MinIO processed upload
↓
pandas DataFrame

This keeps source-specific API handling isolated while producing one canonical downstream schema.

3. Canonical Job Model

Normalized fields:

title
company
location_raw
country
remote

The ClickHouse loader adds:

This schema is the contract between source ingestion and analytical storage.

4. Storage Layers

Local development artifacts:

data/raw/
data/processed/

MinIO object storage:

raw/source=<source>/dt=<date>/
processed/source=<source>/dt=<date>/

Raw API responses remain separate from normalized datasets so source data can be inspected or reprocessed independently.

5. Multi-source Pipeline

Main application entry point:

src/pipelines/run_jobs_pipeline.py

Release flow:

run_arbeitnow()
run_remoteok()
run_jooble()
       ↓
normalized DataFrames
       ↓
combine_normalized_batches()
       ↓
exact deduplication
       ↓
run_loader(combined_df)
       ↓
ClickHouse
       ↓
refresh marts

The normal pipeline passes the combined DataFrame directly to the ClickHouse loader instead of re-reading intermediate CSV files.

6. Deduplication

Version v1.0.0 uses deterministic exact deduplication.

Stages:

(source, source_job_id)
↓
normalized url

More aggressive fuzzy or semantic matching is intentionally outside the first release.

11. Accepted v1 Limitations

limited automated test coverage
simple country normalization
keyword-based skill extraction
exact rather than fuzzy deduplication
no independent failed-source retry flow
no dedicated monitoring/alerting layer
local rather than cloud deployment

These are post-v1 development opportunities rather than blockers for the released portfolio version.
